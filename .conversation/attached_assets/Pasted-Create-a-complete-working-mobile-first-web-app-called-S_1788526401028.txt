Create a complete working mobile-first web app called "SignSpeak – Sign Language Translator".

IMPORTANT:
Build the entire application yourself. Do not ask me to manually create files or paste separate code unless absolutely necessary. Create all required files, install/configure dependencies, and fix all errors automatically.

APP PURPOSE:
A person stands in front of the phone camera and communicates using supported sign-language gestures. The camera detects the person's hand, recognizes supported gestures, converts them into English text, and can speak the translated text aloud.

IMPORTANT LIMITATION:
This is a prototype, not a complete universal sign-language translator. Start with a small, clearly defined set of supported gestures. Never show a random word or pretend a gesture was recognized when it was not.

Hand Landmarks
   ↓
Gesture Recognition
   ↓
English Translation
   ↓

   ↓

2. CAMERA

When the user taps "Start Translating":

- Request camera permission only after the button is pressed.
- Open the phone's front-facing camera.
- Use:
  navigator.mediaDevices.getUserMedia()
- Prefer:
  facingMode: "user"
- Use video constraints suitable for mobile devices.
- The video element must use:
  autoplay
  playsinline
  muted

Do NOT automatically request camera permission when the page first loads.

Display a clear camera preview.

Add:
- "⏹ Stop Camera" button
- Camera status message

Handle these errors clearly:
- Permission denied
- Camera unavailable
- Browser does not support camera
- Insecure/non-HTTPS context

If camera permission is denied, show instructions explaining how to allow camera permission.

3. HAND DETECTION

Use a real browser-compatible hand tracking/computer vision solution.

Prefer a current, supported MediaPipe hand-landmark solution such as MediaPipe Tasks Vision.

Do NOT use fake hand detection.

Continuously process frames from the live camera.

Detect:
- One hand
- Hand landmarks
- Finger positions
- Palm/hand orientation where useful

Show a small status indicator:

"Hand detected ✓"

or

"Show your hand in front of the camera"

4. SIGN/GESTURE RECOGNITION

Create a separate, well-organized gesture recognition module.

For the first prototype, support these five clearly defined demo gestures:

- HELLO
- YES
- NO
- THANK YOU
- HELP

The recognition must be based on actual detected hand landmarks and gesture rules/model logic.

Do NOT:
- choose words randomly
- change the word every few seconds
- pretend that any hand movement is a correct translation
- use fake camera data

If reliable recognition for one of these gestures cannot be achieved using simple landmark rules, display "Recognizing..." rather than giving a false translation.

Make the recognition system modular so a trained sign-language ML model can replace/upgrade the rules later.

5. STABILITY / CONFIDENCE

Do not translate a gesture from one accidental frame.

Require the same gesture to be detected consistently across multiple frames before accepting it.

Add a confidence/stability mechanism.

Display:

"Recognizing..."

then, when stable:

"Translation: HELLO"

Prevent the same gesture from being spoken repeatedly every frame.

Add a cooldown/debounce period.

7. TEXT TO SPEECH

Handle browsers that restrict automatic speech.

If automatic speech is blocked, show:

"Tap Speak Again to hear the translation."

Do NOT require a separate paid text-to-speech API.
